# Chapter 4: 优选分频比表 (32)


在[上一章：智能控制电路 (3)](03_智能控制电路__3__.md)中，我们认识了整个系统的“大脑”——`智能控制电路`。我们知道它能够根据当前的温度和目标频道，做出最明智的决策。但你可能会好奇：这个“大脑”的智慧从何而来？它又是如何知道在什么情况下该用哪个参数的呢？

答案就藏在一本预先编写好的“武功秘籍”里。这本秘籍，就是我们本章要学习的主角——**优选分频比表 (32)**。

## 什么是优选分频比表？

想象一下，你是一位顶级大厨，要前往世界各地参加烹饪比赛。你知道，在不同海拔、不同温度下烹饪同一种食材（比如米饭），需要的水量和火候是完全不同的。为了确保每次都能做出完美的米饭，你准备了一个详尽的笔记：

-   **海拔0米，室温25℃**：米水比例 1:1.2，大火10分钟，小火15分钟。
-   **海拔2000米，气温10℃**：米水比例 1:1.5，大火12分钟，小火20分钟。
-   ...

这本笔记，就是你的“优选配方表”。

**优选分频比表 (32)** 在我们的电路中扮演着完全相同的角色。它是一张存储在 `智能控制电路` 内存中的关键数据表。这张表并非实时计算得出，而是由工程师们通过大量实验和测试，预先测量并记录下来的“最佳实践”集合。

它的核心作用是：**为每一个频道，在每一种可能的温度环境下，都提供一个能让信号噪音（寄生特性）最小化的“最佳分频比”**。

## “秘籍”的结构

这张表就像一个二维的电子表格。它的“行”代表不同的频道，而“列”代表不同的温度范围。表格中的每一个单元格，都填入了一个精心挑选的分频比数值。

让我们来看一个简化的例子，灵感来自专利文件中的图2。

| 信道编号 | 低温 (<0℃) | 常温 (0℃-50℃) | 高温 (>50℃) |
| :--- | :---: | :---: | :---: |
| 信道 0 | 135 | **133** | 135 |
| 信道 1 | 135 | 133 | 135 |
| ... | ... | ... | ... |
| 信道 300 | 133 | **135** | 133 |
| ... | ... | ... | ... |
| 信道 600 | 137 | 133 | 137 |

这张表告诉我们：
-   当我们需要切换到 **信道 0**，并且环境是 **常温** 时，使用分频比 **133** 的效果最好。
-   但如果我们想切换到 **信道 300**，同样在 **常温** 下，最佳选择就变成了分频比 **135**。
-   如果环境温度降到了 **低温**，那么对于 **信道 0** 来说，最佳分频比又变回了 **135**。

这完美地解决了我们在[第 2 章](02_寄生特性与温度补偿_.md)中提到的难题：**没有一个固定的分频比能通吃所有情况**。有了这张表，`智能控制电路` 就有了应对各种复杂情况的“法宝”。

## 这张表是如何被创建的？

你可能会问，这些“最优”值是怎么来的？它们并非凭空猜测，而是工程师们辛勤工作的结晶。

创建这张表的过程大致如下：
1.  **搭建测试环境**：工程师们将 PLL 电路放置在一个可以精确控制温度的实验箱里。
2.  **遍历所有条件**：
    -   首先，将温度设定为一个特定值（例如 -10℃，代表低温）。
    -   然后，选择一个信道（例如信道 0）。
    -   接着，尝试多个不同的分频比（例如 133, 134, 135, 136, 137...）。
3.  **测量与记录**：对于每一种组合（温度、信道、分频比），都用精密的仪器测量输出信号的“纯净度”（即寄生特性有多低）。
4.  **选出最优解**：在所有尝试过的分频比中，选出那个让信号最纯净的值，并把它填入表格的对应位置。
5.  **重复，重复，再重复**：对每一个信道、每一个温度区间，都重复上述过程，直到把整张表格填满。

这个过程虽然繁琐，但它确保了表格中的每一个数据都是经过实际验证的“最优解”。

## “查表”的艺术：代码如何实现

当 `智能控制电路 (3)` 需要决策时，它执行的就是一个简单的“查表”操作。让我们用一段伪代码来模拟这个过程。

假设这张“秘籍”被存储在一个二维数组 `optimal_ratios_table` 中。

```c
// 定义温度范围的常量
#define TEMP_LOW 0
#define TEMP_NORMAL 1
#define TEMP_HIGH 2

// 优选分频比表 (32) 的一个简化版数据结构
// 实际中可能更复杂，但这展示了核心思想
// 行代表信道，列代表温度范围 [低温, 常温, 高温]
int optimal_ratios_table[601][3] = {
    {135, 133, 135}, // 信道 0
    {135, 133, 135}, // 信道 1
    // ... 此处省略大量数据 ...
    {133, 135, 133}, // 信道 300
    // ... 此处省略大量数据 ...
    {137, 133, 137}  // 信道 600
};

// 智能控制电路 (3) 内部的查表函数
int find_optimal_ratio(int channel, float temperature) {
    int temp_range;

    // 1. 判断当前温度属于哪个范围
    if (temperature < 0) {
        temp_range = TEMP_LOW;
    } else if (temperature <= 50) {
        temp_range = TEMP_NORMAL;
    } else {
        temp_range = TEMP_HIGH;
    }

    // 2. 根据信道和温度范围，从表中直接取出最优分频比
    return optimal_ratios_table[channel][temp_range];
}
```
**代码解读**：
1.  我们用一个二维数组 `optimal_ratios_table` 来代表我们的“秘籍”。
2.  `find_optimal_ratio` 函数接收两个参数：目标 `channel`（信道）和当前 `temperature`（温度）。
3.  函数首先根据温度值判断它属于“低温”、“常温”还是“高温”中的哪一类。
4.  最后，它使用 `channel` 作为行号，`temp_range` 作为列号，直接从二维数组中“查”出对应的最优分频比并返回。

这个过程非常高效，因为它避免了任何复杂的实时计算，只是一个简单的内存读取操作。
